# 检索覆盖与证据排序优化（2026-10-15）

本轮保持既有120条golden、相关文档标注（qrels）、top_k=5及门槛不变，目标是修复检索链路并使真实指标超过Recall@5≥0.6、MRR≥0.4、NDCG@5≥0.5。

## 修改及边界

1. **跨查询排名融合**：同一条文在多个查询中命中的排名共同贡献RRF分数，再做每文档3个块的配额；不再由第一次命中决定候选。条文身份使用文档、章节和完整正文，避免前80字相同但法律条件不同的条文被错误合并。
2. **三库候选隔离**：dense及BM25使用一致的文档类型和来源过滤；不再将全库BM25结果混入每个单库召回。同一批查询只向量化一次，三个库复用向量，3个查询由最多9次embedding调用变为1次批量调用。
3. **文档级证据复核**：cross-encoder先为候选条文排序，再将前30篇不同文档及各自最多3段正文交给现有轻量模型判断实际支持程度。提示词区分直接规定、适用制度与起草示例，不为排序任务提供golden标注或参考答案。最终返回的证据仍是实际检索到的原始块。
4. **故障降级**：模型排序编号须为不重复、有效范围内的整数，并覆盖所需条数；非法、空输出、异常及20秒超时均回退cross-encoder文档顺序，不采纳部分非法排序。可用 `RAG_EVIDENCE_RERANK_ENABLED=false` 关闭复核；候选数与超时分别通过 `RAG_EVIDENCE_RERANK_DOCS`、`RAG_EVIDENCE_RERANK_TIMEOUT` 配置。
5. **短结构化任务预算**：仅对DeepSeek官方端点的短任务请求设置 `thinking.type=disabled`，保留调用方显式选项；其他供应商不接收该字段，常规专家审阅不因这一选项自动改变模式。意图/质检等结构化调用、查询改写及证据排序使用短任务配置。参考 [DeepSeek官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。实测自拟短JSON请求的输出token由126降至10，正文均完整；该例不代表长任务固定节省比例。
6. **查询与评测可检查性**：查询改写提示词移至Markdown，缓存包含请求的变体数量；支持显式关闭改写。正式门禁脚本增加受控并发、逐题JSON输出及失败清理，阈值判断维持原值。

`rag_query_expansion.md` 与 `rag_evidence_rerank.md` 由现有 `load_prompt()` 加载，API/SSE结构保持兼容。没有增加依赖，没有修改 `.env`、用户合同及既有 `run_dev.py` 改动。

## 实验方法

- 固定语料为69篇、474个块（制度265、法规171、模板38），没有增删资料或qrels以提高分数。
- 共享Qdrant在本轮连接检查时不可达；从上一轮完整备份恢复到隔离的本地Qdrant，保留相同原向量。两个比较管线共享该索引和BM25，均真实调用embedding、rerank和证据排序模型，不使用模拟分数。没有覆盖共享库或用户原索引。
- 旧管线代码固定为提交 `5e555741b510870d45811d4266e12c31b4e9ffc8`。对每道题固定同一组查询变体并复用同一批真实embedding，避免查询改写波动污染比较；15条开发题按golden顺序每8条选1条，其余105条在方案确定后评测。
- 开发时比较过跨查询融合、同文档合并精排和添加采购背景等方式。单靠这些方式没有稳定提高Recall，采购背景泛化还降低了开发指标，因此未将其作为最终方案。采用证据复核后再进行完整120条比较；最终开发题表现并非每项都提高，105条验证题改善更明显。
- 使用 `text-embedding-v4`（1024维）、`qwen3-rerank`、`deepseek-flash`，query_variants配置为3、per_doc_quota=3、证据复核最多30篇。开发题复用已保存的查询计划，其中个别问题仅有原查询；新旧管线对同一问题使用完全相同的计划。
- 已匿名逐字节核验64篇本地资料与公开GitHub语料一致，另外5个学校公开来源页面均HTTP200。真实评测仅外发这些知识库片段，不读取或发送用户上传的合同。

Recall提升约5.68个百分点。105条验证题Recall由0.5828提高至0.6478、NDCG由0.6429提高至0.6998，所有120条均未触发证据排序降级。15条开发题Recall为0.6124，略低于同查询旧管线0.6129，不将开发结果描述为全面提升。

逐题检索结果、同查询旧管线结果、查询计划、阈值、源码摘要和独立门禁复测一并记录在 [原始JSON报告](rag-eval-2026-10-15.json)。跨10月12日与本轮运行时，执行环境及查询计划不同，主要依据上表的本轮成对比较判断提升。成对评测中新增20题Recall/Hit均为1.0，MRR为0.975，未将其描述为全部首位命中。

## 使用与验证

```powershell
cd backend
# 使用当前已配置的Qdrant及模型；报告使用新路径，脚本拒绝覆盖旧报告。
uv run python scripts/gate_metrics.py --recall5 0.6 --mrr 0.4 --ndcg 0.5 --concurrency 2 --output ../docs/new-rag-run.json
```

证据复核增加一次有候选文档数、输出预算和超时限制的LLM调用，需要在质量、响应时间与token成本之间选择。成对驱动记录的平均search耗时从0.413秒增至1.366秒；该值排除了预先执行的查询改写及embedding，且并发为2，不能当作端到端延迟或负载压测。关闭复核可降低调用成本，但本报告的最终指标不能直接作为关闭后的指标。长文档、未提供的材料、法规现行性和法律结论仍须单独验证；检索指标不等于审阅结论的法律正确率。

本轮无key后端120项测试通过，覆盖融合、过滤、不同条件条文保留、embedding复用、查询缓存、模型参数隔离、排序编号校验、超时/异常降级、门禁并发与报告。共享Qdrant需恢复连接后再验证在线环境。

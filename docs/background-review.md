# 后台审阅

智能审阅页面通过 `POST /api/reviews/jobs` 发起后台任务（202），不再依赖页面保持 SSE 连接。切换模块、刷新、关闭浏览器或退出登录均不取消已接受的任务；同一用户再次登录后可从审阅记录恢复进度和结果。完成摘要和最终风险点一同提交数据库。其他页面显示活动任务入口，并提示任务完成。

审阅页和其他页面的任务提示均提供“停止审阅”。取消请求先进入 `cancelling`，后台关闭 Agent 推理、释放锁后进入 `cancelled`。发起准备期间也可以取消；如果服务器已接受任务，则继续请求停止。停止或失败时展示的初步意见会明确标注为未完成，不能当作完整结论。

## API

所有接口要求登录，仅访问当前用户的任务：

| 接口 | 行为 |
| --- | --- |
| `POST /api/reviews/jobs` | 接受与旧 `/reviews/start` 相同的请求，立即返回任务快照 |
| `GET /api/reviews/jobs?limit=20` | 最近任务，活动任务优先；上限 100 |
| `GET /api/reviews/jobs/{id}` | 恢复进度、初步意见或完整结果及摘要 |
| `POST /api/reviews/jobs/{id}/cancel` | 幂等停止；已完成任务保持完成状态 |

前端通过应用级 Pinia store 轮询活动任务，正常每两秒更新；断线保留已展示内容，每五秒重试。账号变化清除本地视图并忽略旧请求响应。旧 `/reviews/start` SSE 接口保留兼容，其连接生命周期行为不变。

## 运行方式与边界

- 新增 `review_jobs` 表保存任务状态及快照。项目启动时已有的 `Base.metadata.create_all` 会创建新表，无须修改既有表列或清空数据。更新后重启后端及前端即可使用。
- 推理运行在 API 进程的独立 asyncio 任务中，使用独立数据库会话，并继承启动时后台模型、提示词配置快照。
- Redis 按用户和合同加锁，阻止跨会话、跨 worker 重复审阅同一合同；取消标志可由任意 worker 写入，执行 worker 每 0.5 秒检查。租约每五秒续期，最终提交再次校验审阅锁；停止与完成通过数据库行锁协调。
- 当前实现不包含独立任务队列或故障后自动重跑。后端重启会中断正在运行的推理，已保存的完整结果不丢失。正常退出记录中断；进程崩溃后租约最多 30 秒失效，读取任务时将遗留状态收敛为“未完成”，用户可手动重新发起，避免自动重试产生额外调用。
- 活动任务的会话不能删除。已结束任务可随会话一起清理。

回归测试使用 SQLite、fakeredis 和模拟 Agent，不调用真实模型或外部网络。生产 MySQL/Redis 多进程及真实供应商联调需要在部署环境验证。

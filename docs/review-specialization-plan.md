# 通用底座与分类专项检查实施计划

目标：保留六个通用风险维度，在同一 Agent 流程中按合同类型启用专项检查、提示词与检索方向。覆盖当前 12 个默认类型；未知、自定义或未分类类型采用通用审阅，不推断其属于政府采购或高校业务。

## 实施与测试顺序

| 步骤 | 实现 | 验收门槛 | 状态 |
| --- | --- | --- | --- |
| 1 | 不可变分类配置、检查项标识、12 类映射与通用回退 | 默认类型覆盖、标识唯一、六维合法、未知类型与配置隔离测试 | 已通过 |
| 2 | 合同类型与配置接入实际 Agent、后台任务及提示词 | 真实传参、类型优先级、并发上下文隔离、现有 Agent 回归 | 已通过 |
| 3 | 分类检索方向、工具上下文及检查项路由 | 相关条款进入对应专家、检索不丢通用依据、不把类型当适用事实 | 已通过 |
| 4 | 12 类专项检查细则、误报边界与分类样例 | 每类相关/无关样例、已充分约定不机械判缺失、缺证据不确定断言 | 已通过 |
| 5 | 当前任务及历史中保存、展示实际审阅范围与清单版本 | 新旧协议兼容、历史快照不随当前配置变化、前端展示与后台任务测试 | 已通过 |
| 6 | 全量回归与运行说明 | 后端 lint/pytest、前端 lint/test/build、golden 静态门禁 | 已通过 |

每一步先运行对应测试，通过后进入下一步；发现失败先修复，不用删除测试或降低已有门禁的方式继续。

## 共用与专项边界

- 共用底座：主体资格与合规、财务与付款、知识产权与保密、违约责任与解除、验收交付与质保、争议解决与管辖。
- 分类范围：货物采购、工程建设、信息化项目、运维与维保、物业与餐饮、租赁服务、咨询与评估、检验与检测、教育与培训、法律与审计、文化与知识产权、其他服务。
- 专项配置只说明需要检查的问题，不是法律依据或风险结论。触发关键词只用于分发检查，不能直接输出“缺失”“违法”等结论。
- 采购、招投标、学校身份、地区、资金来源及主体角色的适用性，以合同材料及真实证据判断，不从类型名称或默认提示词推出。
- 已有法规证据与质检保护继续保留。复用现有语料，不新增未经核实的法条、强制期限或比例；覆盖不足保持待核实，不承诺全部类型达到生产专业验收标准。
- 历史中记录的是本次采用的配置与计划检查范围；不能把“配置了 N 个检查项”显示成“已核验 N 项”。版本指分类检查清单版本，后台提示词仍使用任务启动时的配置快照。
- 本次不覆盖或提交用户原有启动脚本改动；合同比对修复等已有未提交工作保留。

## 验证记录

实施过程中逐步追加测试命令与结果。真实模型、多供应商与专业人员审核属于后续效果验收；离线测试只证明程序行为与已编写样例的约束。

- 第 1 步：`pytest tests/test_review_profiles.py -q`，9 项通过；对应 ruff 通过。
- 第 2 步：分类配置、类型绑定、运行时配置与 Agent 四组测试，共 49 项通过。原后台提示词仍生效，分类上下文追加在其后，测试同时验证两者。
- 第 3 步：逐类路由、专项与通用检索、工具、RAG、证据核验共 64 项通过。
- 第 4 步：分类细则、并发隔离、类型绑定、旧 Agent、法律保护与审阅接口共 111 项通过。修复测试客户端预导入别名绕过全局 mock 的隔离缺陷，并增加禁止构造真实提供商的验证；在四类供应商密钥均清空的条件下复测通过。
- 第 5 步：后台与历史、类型绑定、配置共 53 项通过；前端 72 项通过，lint 和生产构建通过。历史快照保存当次清单，不按当前类型重建旧记录。
- 第 6 步：最终后端全量 403 项通过（供应商四类密钥均清空）；前端 72 项、ruff、ESLint、类型检查及生产构建均通过。golden 120 题和 35 个关键场景的静态资料门禁通过。提示词主体适用边界另做 50 项定向复核通过。
- 最后复核补齐：未分类文件不能通过请求参数选择后台已停用的类型；明确条款已经排除某事项时，可记录有已读正文依据的不适用，避免机械要求阅读无关条款。
- 实际运行与状态解释见 [分类审阅说明](review-specialization.md)。尚未执行真实模型、真实业务样本或专业人员的效果验收；不将离线测试数解释为法律准确率或全面专业覆盖。

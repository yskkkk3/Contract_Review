# 合同审阅历史

侧栏“审阅历史”展示当前账号的全部已保存记录，支持按合同名称、审阅状态筛选和分页，按发起时间倒序排列。智能审阅页也提供历史入口；合同管理每行的“审阅记录”仅查看该合同的历史。

“查看详情”展示审阅配置、发起及结束时间、风险点、采纳状态，以及已保存的摘要和建议。未完成任务的意见会明确标注为初步意见；依据核验未完成时显示“待补查”。后台任务状态变化后，历史列表及已打开的详情会同步刷新，也可手动刷新。

“再次审阅”将合同、立场、尺度、类型和补充说明带入审阅表单，由用户确认或调整后启动新的审阅会话。不会自动调用模型，也不覆盖选中的历史记录。原合同尚未解析或任务仍在运行时不允许重复发起；已停用的合同类型需要重新选择。

## 接口

| 接口 | 返回 |
| --- | --- |
| `GET /api/reviews/history` | 分页元数据：`items / total / page / page_size` |
| `GET /api/reviews/history/{id}` | 单次审阅的完整详情与配置 |

查询参数：`title`（文件名子串，按字面匹配）、`status`、`file_id`、`page`（从 1 开始）、`page_size`（1–100，默认 10）。记录时间携带 UTC 时区，前端按浏览器时区显示。列表不返回风险正文；详情按需加载。

MySQL 查询将后台任务的字符串 ID 和旧版任务的数字 ID 分列合并，展示用的 `legacy-` 编号在应用层生成，避免列排序规则与连接排序规则不同导致 `UNION` 报 1271。此修复无需修改数据库排序规则或迁移数据。

接口同时检查任务、会话及合同的归属，只返回当前账号的数据。前端在账号变化时清空历史，并忽略旧账号的在途响应；快速切换查询、详情或离开页面后，旧响应不会覆盖当前界面。

## 数据兼容与保留

- 新后台审阅直接读取 `review_jobs` 中的持久化快照。
- 旧版仍保存在 `review_tasks / review_results` 中的记录也能查询。旧版没有存储摘要，因此明确提示“未保存摘要”，不会重新生成或推断历史结论。
- 同会话重审成功时，在替换旧结果前以同一数据库事务保存历史快照。失败或停止不会替换已有成功结果。
- 已被旧代码覆盖或删除的数据无法凭空恢复。显式删除会话仍会同步删除该会话的审阅历史。
- 本次功能不增加数据库表或修改既有表列，沿用后台审阅的 `review_jobs` 表；更新后重启后端并更新前端构建即可。
